# Radix and the floating layer: lifecycle, positioning, dismiss, focus

Status: accepted

Revised: popover was cut from batch 2 by issue #50 and is no longer a component in this system. Every rule below stands unchanged for the four remaining floating components. The `--popover` token keeps its name and still refers to the shared floating surface.

Revised again by the dialog spec (issue #51), in two places. Escape gains one exception, a pending dialog. The portal gains one exception, exhibition mode for documentation. Both are marked inline below.

Revised a third time by the tooltip spec (issue #54), in two places. The surface rule gains an exception, an inverted tooltip with no border. The dismiss rule's pointer-leave clause is made precise, because tooltip content stays hoverable. Both are marked inline below.

Revised a fourth time by review of the tooltip build (issue #71), in three places. Exhibition mode gains its own provider, its positioning is described accurately, and the dismiss rule's hoverable-content clause gains the normative citation that settles it. All three are marked inline below.

Batch 2 is dialog, dropdown-menu, select, tooltip, and tabs. The floating-layer grilling (issue #49) fixed one contract that the four floating components quote instead of re-deciding. It also settles the Radix choice recorded in the batch-2 map (issue #48), together with the motion-lifecycle answer that made the choice affordable.

## Decision

- **Radix for all five batch-2 components.** `radix-ui` is already a dependency and batch 1 uses it in `checkbox.tsx` and `switch.tsx`. Tabs is not floating but takes Radix anyway for the roving-tabindex keyboard path.
- **Radix owns mount and unmount.** No `forceMount`, no `AnimatePresence`, no component-owned `open` state, no controllable-state hook. Enter and exit are CSS animations, which is what Radix's own `Presence` waits for.
- **The spring survives as CSS.** `motion@13.1.1` re-exports `motion-dom`, whose `spring()` prints a CSS shorthand: `spring({ visualDuration: 0.15, bounce: 0.3 }).toString()` gives `250ms linear(0, 0.4188, 0.869, 1.0326, 1.04, 1.0153, 1.0011, 1)`, and `bounce: 0` gives `350ms linear(0, 0.3049, 0.6506, 0.8453, 0.936, 0.9746, 0.9902, 0.9963, 0.9986, 0.9995, 1, 1)`. These are the same curves `springBounce` and `springSettle` run in JavaScript, sampled into `linear()`. The overshoot to `1.04` is the playfulness, and it is preserved.
- **Durations: enter 250ms on the bounce curve, exit 150ms on the settle curve.** The enter keeps its full length or the overshoot is clipped. The exit is compressed because nobody watches a thing leave, and holding the node for 350ms delays focus returning to the trigger.
- **Portal.** All four mount to `document.body`, always. No `container` override prop. **One exception, from issue #51: `exhibitionMode`.** A boolean root prop, default `false`, on every floating component. When `true` the component renders inline with no portal, with Radix `modal` set to `false` internally, so it also drops the focus trap, the scroll lock, the outside-pointer block, and `aria-hidden` on the rest of the page. Dialog renders its own plain `div` scrim in this mode, because Radix renders no overlay when `modal` is `false`. It exists for one purpose: the docs `ModePreview` shows two open copies side by side, one per mode. It is not a `container` prop and does not make modality a prop; `modal` stays unexposed. **Inline is about token inheritance, not placement (issue #71).** Radix's popper positions with `strategy: "fixed"` in every mode, so skipping the portal changes only which theme scope and stacking context the content sits under; no `relative` ancestor is required and none is added. **An exhibited component renders inside its own provider (issue #71)** where its kind has one, so a permanently open exhibit does not consume the app provider's shared timing state.
- **Modality is fixed per component kind, never a prop.** Dialog is modal. Dropdown-menu and select are modal. Tooltip is non-modal. A component that would need modality as a prop is a dialog under another name.
- **Positioning: `side` and `align` are props, the rest is fixed.** Defaults `side="bottom"`, `align="center"`; tooltip defaults `side="top"`. Fixed by the system: `sideOffset: 8`, `alignOffset: 0`, `avoidCollisions: true`, `collisionPadding: 8`. At a viewport edge content flips first, then shifts. No clamp, no `hideWhenDetached`.
- **Open state is forwarded, not reimplemented.** All four Radix roots already accept `open`, `defaultOpen`, and `onOpenChange`; select adds `value`, `defaultValue`, and `onValueChange` as an independent axis. Wrapper props extend `React.ComponentProps<typeof Root>` and spread onto `Root`, never onto `Content`.
- **Motion shapes.** Anchored content scales from `0.96` with `transform-origin: var(--radix-popper-transform-origin)`, so content that flipped still grows from its trigger. Dialog scales from `0.98`, because 4% of a 500px dialog is a lurch where 4% of an anchored panel is a pop. The overlay animates opacity only; it is `fixed inset-0` and scaling it would show a gap at the screen edge.
- **Dismiss is fixed, with two props in the whole layer, both on dialog.** Escape always closes, everywhere, and is never configurable, **with one exception from issue #51: a pending dialog.** Dialog's `pending` prop, default `false`, marks an operation running inside the dialog. While `true`, Escape, outside click, and the dialog's own close button do nothing, and the close button renders disabled. Pending is the only state in the layer that blocks Escape; an operation that runs outside the dialog does not set it, and the dialog stays closable. Outside click closes all three non-dialog layers; choosing an item closes dropdown-menu and select; tooltip also closes on pointer leave, blur, and any pointer-down. **Pointer leave means leaving both the trigger and the tooltip (issue #54):** Radix's hoverable content stays on, so the pointer may cross the 8px gap onto the tooltip and it stays open until the pointer leaves that too. **Hoverable content is normative, not a preference (issue #71):** WCAG 2.1 SC 1.4.13 (Content on Hover or Focus, Level AA) requires that content triggered by pointer hover remain visible while the pointer moves onto it, and its only exception is presentation the user agent controls. `disableHoverableContent` is therefore never set and never exposed, at the provider or per instance, whatever it would buy for pointer speed. The other prop is dialog's `dismissible`, default `true`, which disables outside-click dismissal only and is permanent where `pending` is temporary. Radix's `onPointerDownOutside` and `onInteractOutside` are not passed through.
- **Focus follows Radix's defaults unmodified.** Dialog traps focus. Dropdown-menu and select move focus into the list, which the arrow-key and typeahead path depends on. Tooltip never takes focus. Focus returns to the trigger on close in every case. No `initialFocus` prop.
- **Scroll lock follows modality.** Dialog, dropdown-menu, and select lock the page through `react-remove-scroll`, already installed as a Radix dependency. Tooltip does not.
- **Stacking is one `z-50` on every floating surface**, dialog overlay included. No per-kind z-index scale. Everything portals to `document.body`, so equal z-values resolve by mount order and the layer opened later wins — the correct answer for a dropdown inside a dialog or a tooltip on a dialog's close button. Escape unwinds innermost-first through Radix's dismissable-layer stack.
- **A floating surface separates by a surface step plus its border, not by depth.** Dark mode already did this: `--background` neutral-950 under `--popover` neutral-900. Light mode now matches — `--popover` becomes `var(--color-neutral-50)` against a white `--background`. This answers the flip condition in ADR 0003. **One exception, from issue #54: tooltip inverts.** It paints `bg-foreground text-background` with no border, so light is white text on neutral-950 and dark is neutral-950 text on neutral-50. A tooltip is a label, not a panel, and it takes the largest surface step the palette offers instead of a step plus a border. It does not read the `--popover` token.
- **The dialog scrim is a solid palette color at element opacity**: `--color-neutral-950` animated from `0` to `0.5`. No color alpha is introduced, so the flip condition in ADR 0004 is answered by declining to flip.
- **The shared item is CSS only.** A `floating` registry item carries three keyframe pairs — anchored, dialog, overlay — and their `--animate-*` variables with durations and easings baked in. It holds no TypeScript. Components depend on it and write one class per direction.

## Rationale

- The known conflict is that Radix deletes floating content the moment it closes, and decides when by waiting for a CSS `animationend` event. A `motion` spring drives transforms from JavaScript and fires no such event, so the exit never plays.
- The usual fix is `forceMount` plus `AnimatePresence`. It works, and it costs roughly twenty duplicated lines in each of five components, a hand-written controllable-state hook, a `pointer-events` guard on the exiting layer whose dismiss handlers are still live, and the fussiest force-mount case of all in select's viewport.
- `spring().toString()` removes that entire cost. The only thing `forceMount` buys over it is interruption fidelity: a JavaScript spring interrupted mid-flight continues from its current position and velocity, where a CSS animation restarts from its fixed start frame. On a 150ms fade-and-scale that is a small price, and it is paid only when a layer is toggled fast.
- Fixing modality per component kind rather than exposing it keeps dismiss, focus, scroll lock, and stacking from becoming conditional on a prop.
- `tw-animate-css` was rejected for the keyframes. It is a third-party dependency we would push onto every consumer, and ADR 0001 already requires each registry item to carry its own `animate-*` utility rather than borrow one.

## Consequences

- **ADR 0001 is revised twice.** CSS keyframes now carry floating enter and exit, not continuous animation only; the engine split there assigned enter/exit to `motion`. And "under 200ms" means visual duration, not wall clock — batch 1's springs already ran 250ms and 350ms end to end, JavaScript just never made anyone write the number down.
- **ADR 0004 is widened, not broken.** It lists element opacity as fine for disabled states and motion. The scrim is a third sanctioned use. Color alpha stays banned repo-wide with no exception.
- **ADR 0003's flip condition is answered** with the surface step named above, not with a shadow.
- **The theme item changes one value**: light `--popover` moves from `var(--color-white)` to `var(--color-neutral-50)`.
- **A new `floating` registry item** joins the registry, and the four floating components declare it as a dependency. Dialog's build creates it with all three keyframe pairs at once (issue #51); the values are fixed above, so writing the anchored pair before its first consumer is transcription, and it keeps three later sessions from editing one shared file.
- **Two rules above now carry an exception each** (issue #51). Escape yields to a pending dialog, because a modal that closes mid-submit leaves a request running with no owner on screen. The portal yields to `exhibitionMode`, because a portalled component escapes the docs `ModePreview` panels and takes the site theme, so the side-by-side mode view could not show it at all. Both exceptions are the narrowest that solve the problem, and neither is a `container` or `modal` prop.
- **Three corrections land from the tooltip build review** (issue #71). An exhibited tooltip is controlled at `open={true}`, and Radix broadcasts a `tooltip.open` document event that every mounted content answers by calling its root's close path; a controlled root still fires `onOpenChange`, which arms the provider's skip timer at the moment some _other_ tooltip opens. Any page carrying an exhibit therefore had no working skip window. Giving the exhibit its own provider contains the broadcast. Separately, Radix's hoverable-content grace area is tracked by a bubble-phase `document` listener that loses to React's root handler, so a pointer path sparse enough to fire two or three events between adjacent triggers strands the first tooltip and opens no second one until the pointer moves again. That is upstream and unfixable here without owning `open` state; it is documented on the tooltip page rather than worked around.
- **The surface rule carries one exception** (issue #54). Tooltip inverts and drops its border, because a neutral-50 chip behind a 1px border vanishes over a busy page where a 448px dialog does not. The `--popover` token still describes the surface of dialog, dropdown-menu, and select.
- The four floating component specs quote the names above for portal, positioning, dismiss, focus, and motion rather than restating them.
- A consumer's own `position: fixed` header still shifts when the page locks, because `react-remove-scroll` pads the body. Documented for consumers through the `--removed-body-scroll-bar-size` variable, not solved in the registry.
- **Popover is cut from the design system, permanently** (issue #50). It had no distinct job worth a public component, and no Radix package builds on `@radix-ui/react-popover`, so nothing else in batch 2 loses anything. The `--popover` and `--popover-foreground` tokens keep their names: they describe the floating surface that dialog, dropdown-menu, select, and tooltip all paint, not a component we ship. The anchored small form, the filter cluster, and click-to-open help text have no replacement in this system, by decision.
- Exit animation is skipped if an app sets `open` to false and unmounts the component in the same render. Radix needs the component alive to play it. This is true of every lifecycle shape considered.

## Deferred

- **A code-carrying `floating` lib item.** The shared surface is CSS today. Revisit after dialog and one menu component are actually built, per issue #48 — do not guess its shape before two components have used the pattern.
- **A `container` prop for the portal target**, and an `initialFocus` prop. Both wait for a real consumer need.
- **`prefers-reduced-motion`**, still deferred by the standing rule in ADR 0001 and `CLAUDE.md`.
